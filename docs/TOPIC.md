## 1. 주제 한 줄

**"가상 창고형 약국의 근무 직원을 위한 업무 지원 자동화"** — 직원 · 어르신 손님이 묻는 것을 약국 문서로 답하고, 사람이 정할 일(회수 확인 · 현금 차액 · 복약 판단)은 약사 · 약국장에게 넘깁니다.

**입구 · 뒷단 조합**: ☐ A 기본형 ☐ B 메신저 + 헬프데스크형 ☑ **C 자체 웹앱형** (직원 · 어르신 화면 Next.js + 약사 화면 · FastAPI + PostgreSQL)

- 어댑터 담당: FastAPI 뒷단 = 병훈 (연동 · 안정성), 화면 = 해든.
- A로 공통 시나리오를 먼저 통과시킬 시각: 81일차 4교시 중간점검 전 (팀 웹훅 + data-api).
- 어댑터가 시연 전까지 안 되면 A(팀 웹훅 + data-api)로 시연합니다.
- 가산: Slack `#support-alerts` 알림, Jira는 시스템 장애 티켓만 한 방향. 실제/연습 스위치 한 곳, 기본은 연습.

## 3. 범위

| 문의 유형 (4개) | 처리 방식 | 근거 문서 |
| --- | --- | --- |
| 회수 공지가 떴어요 | 근거 + 이관 (긴급, 약사) | `recall-first-response`, `recall-customer-guide` |
| 혼자 하는 첫 마감 | 자동 답변 (현금 차액은 근거 + 이관 → 약국장, 냉장고 온도 이탈은 긴급 → 약사) | `closing-checklist`, `closing-cash-mismatch` |
| 어르신 약 질문 | 자동 답변 (문서 사실 인용 + AI 고지). 같이 먹어도 되나 · 내 경우 → 보완 질문 뒤 약사 이관, 위험 신호 → 긴급 이관 | `senior-cold-sleep-stomach`, `senior-pain-joint`, `senior-safety-signals` |
| 내 접수 건 확인 | 접수 조회 (본인 건만, 연락처 가림) | `request-records-guide` |

- 시간이 남으면 켜는 유형 (정의만): 약이 떨어졌을 때 · 왜 이 금액이에요?
- 본체는 유형 이름이 아니라 처리 방식 4개로 갈라서, 유형을 켜고 끄는 것은 표 한 곳과 문서 묶음만 바뀝니다.

**자동 답변하면 안 되는 경우**: 돈 결정 (차액 처리 · 환불 승인), 약 판단 (같이 먹어도 되나 · 먹어도 되나 · 양 · 끊기 · 온도가 벗어난 약), 처방 조제 여부, 회수 대상 확정과 손님 안내 (약사 승인 뒤), 위험 신호 (숨참 · 가슴 통증 · 출혈 등 → 약사 긴급 + 119 안내), 약국장 전용 규칙을 직원이 물을 때.

**어르신 기능의 단계**: 기본은 `patient_direct` (환자가 직접 묻고 근거 인용 답 — "규제가 풀린 미래를 가정"), 막히면 `pharmacist_approval` (약사 승인 뒤 전달) 또는 `handoff_only` (답 없이 약사에게)로 표 한 줄을 바꿔 내립니다.
